# МТС EnergyTool — каркас решения

Каркас для Hack&Change 2026. Платформа запускает `solution.py` в Docker, передаёт вопросы и базу знаний, забирает `submission.csv` и отдаёт его LLM-судье. Веб-чат вызывает ту же функцию `consult()`, чтобы лидерборд и демо не разъехались.

Учебный пример организаторов обрезает каждый документ до начала файла. Здесь документ режется по заголовкам markdown, а в модель уходит выбранный раздел целиком, если он помещается в лимит цитаты.

## Архитектура

```
questions.csv
    -> dialogue.parse_dialogue
    -> consult(messages)
         -> chunks.load_chunks          разделы markdown
         -> retrieve.rank_chunks        выбор разделов
         -> embeddings и rerank         если заданы ключ и адрес
         -> consultant.build_messages   текст ответа по prompt.txt
    -> submission.csv                   только текст
```

`consult(messages)` возвращает `ConsultResult`:

- `text` — ответ для судьи и для чата, одна строка;
- `sources` — путь файла (`20-products/23-solar.md`), заголовок раздела, цитата, оценка;
- `lead` — черновик заявки. Пока пустой: ФИО, телефон, компания и резюме появляются только после согласия клиента. В CSV заявка не пишется.

Между разными `id` состояние не переносится. В диалоге ответ строится на последнюю реплику пользователя. В поиск попадают эта реплика и факты из предыдущих реплик пользователя, без реплик ассистента.

| Модуль | Кто меняет |
|---|---|
| `solution.py` | сдача: пул, лимиты, CSV |
| `config.py`, `llm.py` | сдача: окружение, повторы запросов |
| `dialogue.py`, `chunks.py`, `contract.py` | каркас |
| `retrieve.py`, функция `rank_chunks` | поиск |
| `consult.py` | сдача: вызывает промпт и поиск |
| `consultant.py`, `prompt.txt` | консультант: форма ответа и правила |
| `web/` | интерфейс. Папки пока нет. Импортировать `consult` из корня |

Форма ответа, границы и уточняющие вопросы записаны консультантом в `prompt.txt`. Каркас этот текст не переписывает.

## Локальный прогон

Из корня репозитория:

```powershell
copy .env.example .env
python -m pip install -r requirements.txt
python check_skeleton.py
python solution.py
```

`DATA_DIR` в `.env` указывает на `_materials`, где лежат `demo_questions.csv` и `knowledge-base.zip`. Платформа кладёт в свой каталог `questions.csv` и тот же архив базы. Скрипт сначала ищет `questions.csv`, затем `demo_questions.csv`.

Без адреса и ключа LLM в `submission.csv` будет 18 непустых заглушек, а в консоли — выбранные разделы. Так проверяется каркас. Содержательные ответы появляются, когда в `.env` есть `LLM_BASE_URL` и `LLM_API_KEY`.

Перед упаковкой:

```powershell
python package_zip.py
```

Архив: `out/submission.zip`.

## Docker одной командой

Нужны Docker и каталог `_materials` в корне. Команду запускать из корня репозитория:

```powershell
copy .env.example .env
docker compose up --build --abort-on-container-exit
```

Результат: `out/submission.csv`.

Порт скрипт проверки не открывает. Для веб-чата в `compose.yaml` зарезервирован сервис на порту 8000. Когда интерфейс его добавит, демонстрация всего прототипа остаётся `docker compose up --build`.

Образ не содержит базу знаний, вопросы и `.env`. Каталог `_materials` монтируется в `/data` только на время локального прогона.

## Переменные окружения

Секреты в код, логи и ZIP не записываются. Имя модели берётся из окружения.

| Переменная | Назначение |
|---|---|
| `LLM_BASE_URL`, `BASE_URL`, `OPENAI_BASE_URL` | адрес OpenAI-совместимого прокси |
| `LLM_API_KEY`, `OPENAI_API_KEY` | ключ LLM |
| `EMBEDDER_API_KEY` | ключ эмбеддера; если пусто — ключ LLM |
| `RERANKER_API_KEY` | ключ реранкера; если пусто — ключ LLM |
| `LLM_MODEL`, `GEN_MODEL`, `OPENAI_MODEL` | модель генерации |
| `EMB_MODEL` | модель эмбеддингов, по умолчанию `baai/bge-m3` |
| `RERANKER_MODEL` | модель реранкера, по умолчанию `qwen/qwen3-reranker-8b` |
| `DATA_DIR` | каталог входных файлов; на платформе приходит снаружи, локально `_materials` |
| `TOP_K` | сколько разделов оставить после лексического отбора, 1–30 |
| `RERANKER_TOP_N` | сколько лучших фрагментов реранкер ставит в начало; в промпт уходят все `TOP_K` |
| `MAX_TOKENS` | предел генерации одного ответа |
| `TEMPERATURE` | температура |
| `MAX_WORKERS` | параллельные вопросы, 1–8 |
| `CHUNKER` | читается из окружения. Нарезка каркаса всегда по заголовкам markdown |
| `PYTHONPATH` | стандартная переменная Python |

Локально, не на платформе, можно задать `SUBMISSION_PATH`. Docker пишет в `/out/submission.csv`.

Вызовы:

- `POST /embeddings` с телом `{"model": EMB_MODEL, "input": ["текст"]}`
- `POST /rerank` с телом `{"model": RERANKER_MODEL, "query": "вопрос", "documents": ["текст"], "top_n": RERANKER_TOP_N}`
- `POST /chat/completions` с `model`, `messages`, `temperature`, `max_tokens`

На 429 и 5xx запрос повторяется один раз, пауза не длиннее 2 секунд. 401 и остальные 4xx не повторяются.

## submission.csv

Колонки `id` и `answer`, UTF-8 без BOM, перевод строки `\n`. Все id из входа, без повторов и без пустых ответов. Переносы внутри ответа заменяются пробелом. Длиннее 10 000 символов ответ обрезается. Поля экранируются кавычками.

## ZIP для платформы

Файлы лежат в корне архива, без общей папки. Внутри: `solution.py`, модули, от которых он импортируется, `requirements.txt`, `README.md`.

В архив не входят база знаний, `questions.csv`, `demo_questions.csv`, `.env`, индекс и кэш. Лимит архива — 128 МБ. `pip install` из `solution.py` не вызывается.

`requirements.txt` содержит только пакеты из списка организаторов и те же версии. Сейчас это `httpx==0.28.1` и `python-dotenv==1.1.1`. Рядом с модулями в архиве лежит `prompt.txt`: без него ответ не соберётся. Новый пакет сначала сверяется с `_materials/requirements.txt`.

## Лимиты платформы

5 сабмитов в сутки на команду, сброс в 00:00 МСК. 8 CPU, 16 ГБ RAM, прогон до 20 минут. Каркас перестаёт начинать новые генерации за 90 секунд до этого предела и всё равно записывает CSV, чтобы файл не потерялся по тайм-ауту. Повторный одинаковый ZIP тратит попытку зря: гипотеза и вывод пишутся в `journal/submits.md`.

Ориентир длины ответа — до 150 слов. Резюме заявки для менеджера этим пределом не связано, потому что в CSV судьи оно не попадает.

## Репозиторий для жюри

Репозиторий приватный. Аккаунту `hack-and-change-2026` нужен доступ на чтение. Базу знаний и исходные выгрузки в открытый репозиторий не класть. На первом слайде защиты — ссылка на репозиторий и порядок проверки. Черновик колоды: `defense/SLIDES.md`.

## Порядок проверки основного сценария

1. `python check_skeleton.py` — парсер диалогов 14–18, нарезка по заголовкам, пустая заявка, форма CSV.
2. `python solution.py` — 18 строк в `submission.csv`, в консоли путь и заголовок выбранного раздела.
3. С ключом LLM: `python compare.py` пишет `сверка.txt` рядом с образцом из `_materials/demo_output.csv`. Вопросы 4, 9 и 18 помечены как примеры из промпта.
4. `python package_zip.py` и отправка `out/submission.zip`, если гипотеза одна и суточный лимит ещё не выбран.

## Известные ограничения

- Без ключа LLM в CSV пишется заглушка «Не могу ответить по доступным фрагментам базы знаний.»
- Лексический отбор идёт по всей базе и сравнивает основы слов. Роутер ветки `search-rag` оставляет только файлы продуктов и из-за этого теряет тарифы, пороги мощности и файл с данными для оценки, поэтому в этот прогон он не входит.
- Заявку каркас не заполняет: телефон не запрашивается, пока клиент сам не согласится.
- Веб-интерфейса ещё нет: нет многошагового чата, кнопки «Новый диалог» и режима отладки.
- Контейнер запускается от root, чтобы примонтированный каталог `out` оставался доступным для записи.
